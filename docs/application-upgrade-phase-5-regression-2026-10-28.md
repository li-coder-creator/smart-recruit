## 4. B组：查询精确边界

固定时间now=2026-10-28T12:34:56。

| 查询 | 已验证的边界 |
| --- | --- |
| LAST_7_DAYS | 起点10月22日00:00:00包含；前一秒排除，后一秒包含 |
| LAST_30_DAYS | 起点9月29日00:00:00包含；前一秒排除，后一秒包含 |
| ALL | 取消下限，仍排除now后一秒；恰好等于now纳入 |
| 默认查询 | 最近30天，每页10条；total与当前页数量分别正确 |
| 同时间三条记录 | 按create_time DESC、id DESC分页，跨页无重复或遗漏 |
| 超末页 | items=[]且保留total，不自动修正成末页 |
| 日期+五种状态组合 | 返回精确预期ID集合和排序 |
| 空白/100字符关键词 | 空白归一、不筛选；100字符合法；101字符拒绝 |
| 非整数/负数/溢出分页、非法状态和日期枚举 | 按契约拒绝 |
| userId/companyId/自定义sort参数 | 不能切换归属或排序，仍查询当前求职者 |
| 无投递用户 | 空列表、总览六项计数均为0 |
| 故意非法状态记录 | 列表、概览、详情明确失败，不拼凑不一致统计 |

概览不受日期窗口影响，按契约统计本人全部历史的当前状态。故意构造的未来异常投递也参与该聚合，
而列表排除未来记录，两者口径不同已明确验证，没有隐式改变契约。
关键词特殊字符的字面匹配已在阶段三验证；本次补充长度和空白等边界。

## 5. C组：历史资料缺失与可见性

22种关联组合包含：四种岗位状态ACTIVE/PAUSED/ENDED/DRAFT，分别与APPROVED/PENDING/REJECTED/企业缺失组合；
另加岗位缺失、简历缺失、简历现属他人、简历空标题、面议空薪资、明确月薪六项。

验证结果：

- 全部22条历史投递在本人列表保留，五种状态统计不依赖展示资料是否齐全。
- companyAvailable仅表示企业存在，PENDING/REJECTED仍为true；jobViewable仅在ACTIVE且APPROVED时为true。
- 岗位缺失时保留原jobId，岗位/薪资/当前企业信息为null；不猜测薪资面议。
- 简历缺失或已属其他人时，保留resumeId，resumeAvailable=false、resumeTitle=null；不会泄露他人标题。
- 空标题但仍存在的本人简历，resumeAvailable=true，不误判删除。
- 空白企业Logo归一为null，由前端提供中性占位。
- 旧historyComplete均保持false，events/interviews为空时返回空数组，不补造时间线。
- 列表与详情的可用标记一致；本人权限不依赖关联展示资料是否存在。
- 其他求职者读取缺失资料投递与读取不存在投递，均返回统一拒绝文案。

孤立引用等历史异常仅在全新隔离库构造。准备时临时关闭该连接的外键检查并立即恢复，未对开发库执行约束关闭或数据删除。
