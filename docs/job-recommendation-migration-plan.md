## 2. 数据结构变更及迁移顺序

选择直接扩展5张原表及新增1张子表；默认值只表达未知，不补造求职身份、经验分类或标准技能。

1. 核对当前服务数据源、MySQL版本和元数据，确认目标新列及子表尚不存在。已有部分结构时停止整份脚本执行，按实际差异审查。
2. 备份5张原表的结构和数据，记录旧列清单与主键；保留可逐行比对的旧值，不能只记COUNT(*)。
3. 在隔离库先执行草案、检查约束与旧请求兼容；本次未执行这一步。
4. 安排暂停写入窗口，逐条执行5个ALTER和1个CREATE，保留每步结果。不要关闭外键检查或忽略SQL错误。
5. 检查9列默认值、新表索引与级联外键；新表应空，旧列与备份逐行一致。
6. 部署支持新字段存在性、来源与版本的后端；新能力入口暂关闭。旧请求回归通过后，再启用新版填写入口。
7. 前端升级后支持用户主动补充。完整推荐功能须等名称/别名与语义校准均完成再验收；未完成时清楚返回待确认原因。

SQL不是自动迁移框架：当前pom.xml未发现Flyway/Liquibase依赖，后续应记录实际执行环境、时间和结果，不能仅以脚本存在认定已迁移。

当前MySQL 8.0.13早于CHECK约束正式执行版本，日期、枚举、版本非负和列表长度必须由应用校验，不能认为写CHECK就受到保护。[MySQL官方说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)
ALTER/CREATE等DDL会隐式提交；失败后已完成步骤不会因ROLLBACK整体撤销，需逐步核对续做。[MySQL事务说明](https://dev.mysql.com/doc/refman/8.0/en/implicit-commit.html)
新子表选择ON DELETE CASCADE以清理纯从属要求；RESTRICT会阻止仍有子行的父行删除，不能直接复制其它模块的外键策略。[MySQL外键说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-foreign-keys.html)

## 3. 回退与兼容限制

- 发生应用问题优先关闭推荐或新版编辑入口，保留新增字段和已填写内容；不自动DROP表列，不从空值反向推断历史。
- 迁移只加列，但仍可能出现DDL锁等待；实际窗口和耗时需在目标环境确认，本阶段不承诺零停机或固定耗时。
- 尚未写入新功能数据时，旧应用按明确列名INSERT/UPDATE通常可继续操作；仍需验证，不能只看编译成功。
- 已存在STRUCTURED岗位后，不能直接恢复旧版本写入口：旧版JobSaveDTO和Mapper会更新required_skills，却不会检查来源、维护子表或递增版本。
- 如需回退应用，应关闭岗位能力写入，或使用保留来源一致性检查的兼容版本；只读页面可继续读取新后端生成的兼容文本。
- 若一定要撤销结构，须先导出全部新数据、停用新读写、逐项确认丢失影响并另行授权；本草案不提供自动破坏性回滚。

## 5. 权限、事务与并发细节

### 简历写入

保持现有路径：POST /resume、PUT /resume/{id}/basic以及经历/技能/意向子接口；本阶段不新增一整套重复CRUD。
写入先requireJobSeeker，再确认resume.user_id；子项通过数据库查真实resume_id，不信任请求体ID。
修改声明和经历均以resume父行作为统一锁，先父后子；声明NONE与新增正式经历不能各自无锁校验后提交。
删除或分类变更后的HAS_EXPERIENCE重置、完成度刷新与实际经历写入同一事务。业务校验失败不得留下半写状态。

### 岗位写入

沿用POST /job、POST /job/drafts、PUT /job/{id}和既有草稿发布路径；所有入口调用同一来源处理与校验逻辑。
企业归属由requireApprovedCompany及数据库company_id确认；先锁job父行，检查能力预期版本，再批量替换子项。
新建岗位先获取主键；若带结构化数组，版本0检查后写子表、来源和版本1。任一步失败包括操作记录失败均回滚。
两次使用同一预期版本提交数组，仅首个成功；第二个等待父锁后发现版本不符应拒绝。
旧文本模式发生真实更改也递增能力版本；STRUCTURED模式的旧客户端更改文本必须拒绝，不能偷偷切回LEGACY_TEXT。
岗位详情缓存仅提交后失效；不在数据库写事务中调用模型。草稿删除继续按既有权限/状态规则，外键自动清理子项。

### 推荐读取

数据库读取阶段使用一致快照取所选简历及候选岗位特征；模型调用在读取事务结束后进行，避免长时间占连接与锁资源。
按来源批量读取能力要求；全局打分再分页。必要的规模边界、批次和超时在接口/模型阶段确定，不用只算普通第一页冒充全局排序。
外部模型只接收必要能力文本；提供模型故障与资料缺失的不同原因，不把不可用降级成匹配0或静默换模型。
